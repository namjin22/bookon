공식 팀 01·02 SQL로 초기화한 로컬 격리 Oracle 11g XE에서 실제 Tomcat 10.1과 팀 JSP를 사용했다. 아래는 Codex가 브라우저 폼과 동일한 HTTP 요청을 보내고 응답을 저장한 검증 결과다. DB 담당의 SQL 하네스와 별개다.

팀 03 v2와 Java 차이
- Java는 학생 행의 ID를 먼저 잠근 뒤 별도 조회에서 학생 상태와 두 대출 건수를 함께 읽는다. 팀 SQL은 잠금과 학생 상태를 한 SELECT에 담고 연체·미반납 건수를 따로 조회한다.
- Java 대출 INSERT는 활성 학생 조건이 있는 INSERT SELECT이며 바인딩은 도서 코드, 예정일, 학생 ID 순서다. 팀 SQL의 VALUES 바인딩은 학생 ID, 도서 코드, 예정일 순서다.
- Java는 반납 전 대출의 학생 ID를 찾고 대출과 동일한 순서로 학생을 잠근다. 없는 번호와 이미 반납을 구분한다.
- Java는 실제 저장한 RETURN_DATE와 DUE_DATE 차이를 먼저 읽고, 양수일 때 연체일수와 학생 ID로 정지를 업데이트한다. 팀 SQL은 LOAN_ID를 사용하여 날짜를 재계산하고 정지 UPDATE 후 화면용 일수를 조회한다.
